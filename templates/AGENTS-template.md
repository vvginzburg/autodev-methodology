## Автономная разработка по AutoDev Codex

Методика: <абсолютный путь к папке установленного autodev-codex>.
Версия: <версия и commit>. Канон: SKILL.md в этой папке; ресурсы относительно неё.
Этот раздел дописывается к существующим правилам, не заменяет их.
Роль конкретной задачи задаёт поручение владельца/оркестратора. Чтение этого
раздела не превращает исследователя или ревьюера в руководителя проекта.

### Возобновление

1. Прочитать autodev/STATUS.md, env-check.md, PLAN.md, DECISIONS.md,
   ESCALATIONS.md и REPORT.md, какие есть; проверить git status и последние
   коммиты. Прошлое «работаю» — старое событие, не доказательство живого агента.
2. Определить фазу по явным отметкам и доказательствам. До реального исполнения проверить поручение на разработку: одобрение содержания плана при поручении только проектировать не разрешает стройку. Нет поручения — предъявить готовые документы и запросить запуск; уже данное поручение не запрашивать повторно. Наличие PLAN.md само
   по себе не разрешает разработку. Нет завершённой 0.A — продолжить её;
   нет согласованного ТЗ/плана — продолжить фазу 1; не завершена 0.B или фаза 2 —
   закончить соответствующую проверку. Отсутствие записи не отменяет известного
   согласия: восстановить запись по доказательствам, не спрашивать повторно.
3. На фазе 3 прочитать SPECIFICATION целиком. Проверить незавершённую задачу,
   сохранённую исходную точку и отчёты по phases/03-development.md. Не удалять
   неизвестные изменения. Открытые вопросы блокируют только зависимые задачи.
   Есть подтверждённый ответ — записать и возобновить работу по нему.
4. Все задачи приняты и автоматические проверки завершены — фаза 4; продукт
   принят владельцем — фаза 5; ретро записано — завершить, а не запускать цикл
   заново. При реальном препятствии записать его и нужное действие.

### Работа

- Полномочия — SPECIFICATION §0.6; правило решений — принцип 14 SKILL.md.
- Цикл задач, STATUS, Git и безопасный возврат — phases/03-development.md.
- Роли — roles/core.md; независимое ревью и поля отчёта — roles/contracts.md.
- Фактическая машина, команды, навыки и разрешённый remote — env-check.md;
  стек — stack.md; грабли — pitfalls.md плюс reference/pitfalls.md методики.
- Другой конвейер не запускать поверх AutoDev. Дополнительные навыки — только
  в совместимых пределах reference/portability.md. При применении назвать навык.
- В конце содержательного ответа прямо сказать, требуется ли действие владельца.
  Уже согласованную доступную работу выполнить до окончания хода. Ожидание
  оформлять видимым вопросом, варианты — с последствиями и рекомендацией.
