# AutoDev — методика автономной агентной разработки

Версия 2.0 · выработана на проекте DocVault (2026-07-06/07) · развивается: см. CHANGELOG.md

## Резюме для человека (1 минута)

Человек **долго проектирует** и один раз отвечает на все вопросы. AI **автономно строит**
и не беспокоит человека: вопросы без ответа в ТЗ решаются самостоятельно и записываются.
Каждую задачу делает свежий агент-исполнитель через TDD, принимает — **независимый
агент-ревьюер**, никогда не тот, кто писал. Каждая принятая задача = git-коммит.
Человек возвращается дважды: на **приёмку** (проверяет руками только то, что существует
в физическом мире: камера, живые устройства, реальные данные) и на **ретро**
(что улучшить в методике). Найденные на приёмке баги чинятся тем же конвейером.

Результат DocVault-калибровки: 16 задач + 4 багфикса за ~2 суток, 76 тестов × 2
платформы, участие человека ≈ 1 час на приёмке.

## Несущие принципы (выстраданы, не менять без ретро-обоснования)

1. **Проверяет не тот, кто писал.** Самопроверка исполнителя систематически завышает
   готовность. Ревьюер перепроверяет фактами: сам гоняет тесты, сам читает первоисточники.
2. **Рабочие агенты — свежие, консультанты — долгоживущие.** Свежий контекст на задачу =
   незамыленный глаз + линейная (не квадратичная) стоимость токенов. Повторяющееся знание
   живёт в файлах (CLAUDE.md проекта, reference/), а не в брифах.
3. **Вопросы не блокируют.** Нет ответа в RRR → разумное инженерное решение → запись
   в DECISIONS.md (дата, вопрос, решение, почему). Человек читает файл после, за 10 минут.
4. **Коммит на принятую задачу.** Git — единственная надёжная память процесса: переживает
   обрывы, лимиты, закрытые крышки. Прогресс = git log, а не самоотчёты.
5. **Первая итерация — только план.** Дальше задачи берутся из PLAN.md, приоритеты
   не переосмысляются (иначе осцилляция). План живой: правки — с причиной в коммите.
6. **Граница автоматизации проходит по физическому миру.** Всё, что проверяемо программно,
   проверяет AI (фейки железа за протоколами — см. roles/). Человеку остаётся камера,
   кабель, живой аккаунт — и это не «тестирование», а финальный сенсор реальности.
7. **Изолируй железо за протоколом с первого дня.** Две реализации сразу: настоящая
   и фейковая; выбор в composition root. Отдельного этапа «подключить настоящее» нет.
8. **Не изобретай — компонуй.** Методика ссылается на установленные скилы
   (superpowers:brainstorming, writing-plans, subagent-driven-development,
   test-driven-development, verification-before-completion) и добавляет слой оркестрации,
   которого в них нет.

## Роли

Ядро (всегда): **оркестратор + исполнитель + ревьюер** — [roles/core.md](roles/core.md).
Полка (по признакам проекта или «правилу второго раза»): [roles/catalog.md](roles/catalog.md).
Правило второго раза: оркестратор делает работу руками второй раз подряд → выделяет роль.

## Быстрый старт нового проекта

1. Прочитай phases/01-design.md → сократический диалог с человеком → RRR.md + PLAN.md
   + CLAUDE.md из шаблонов.
2. Фаза 2 обязательна и заканчивается СМОК-ТЕСТОМ: пустая задача проходит полный цикл
   (агент → сборка → тест → коммит) без единого вопроса человеку. Не зелёный смок —
   не начинай разработку.
3. Разработка по phases/03. Приёмка по phases/04. Ретро по phases/05 — с коммитом сюда.
