# Ревью до коммита

Оригинальный SDD review-package работает с commit refs. В AutoDev коммит
результата следует после независимого ревью; использовать помощник
`scripts/review_candidate.py` для явного снимка рабочего дерева.

1. Оркестратор сохраняет baseline задачи и готовит `scope.json`: точные файлы
   или директории задачи и обоснованные исключения. Не использовать корень
   проекта. В директориях включаются также untracked и Gitignored файлы;
   секреты, runtime и сборку исключить явно с причиной. Область сопоставить
   с брифом, Git и отчётом исполнителя — авторство из одного git status не следует.

```json
{"paths":["src","tests","package.json","package-lock.json"],
 "exclude":[{"path":"tests/cache","reason":"generated test cache"}]}
```

2. Сначала записать и закоммитить переход STATUS «ревью» только файлами
   процесса. Затем остановить записи исполнителей и захватить кандидат в новую папку за
   пределами scope; сохранить рядом бриф, ссылки на SPECIFICATION/DECISIONS
  и свидетельства тестов. Это тоже материалы ревью, не только diff.
   До коммита принятого кода HEAD не менять; новые записи процесса остаются
   на диске. Если кандидат возвращён или отменён, закрыть его, сохранить
   переход и после исправления создать новый снимок.

```sh
python3 "<методика>/scripts/review_candidate.py" capture --repo "<проект>" --scope "<scope.json>" --base "<baseline commit>" --out "<проект>/autodev/reviews/T01-round1"
```

Manifest содержит baseline, before/after, состояние индекса в scope, ID
кандидата и хеш исходного индекса. `objects/<sha256>` хранит точные байты,
включая бинарные файлы и текст целей symlink; режимы — в manifest.
`changes.diff` — удобное представление, не единственное доказательство.
Переименование представлено удалением и добавлением, поэтому данные не теряются.
Помощник не коммитит, не меняет индекс и не удаляет исходники.

3. Независимый ревьюер проверяет кандидат, оригинальные требования и контекст,
   исполняет необходимые сценарии и указывает ID в своём вердикте. Перед
   проверками и после них сверяет рабочее дерево с принятым снимком:

```sh
python3 "<методика>/scripts/review_candidate.py" verify "<пакет>/manifest.json"
```

При возврате сохранить этот пакет. Новый исполнитель — по фазе 3, новый
пакет — с другим именем раунда. Сравнивать before/after и объекты пакетов,
а не неизменившийся HEAD. Изменения после ревью требуют нового снимка и
затронутой проверки; прежний вердикт не распространяется автоматически.

4. После приёмки оркестратор подготавливает индекс только для проверенных
   файлов, явно обрабатывая удаления. До commit:

```sh
python3 "<методика>/scripts/review_candidate.py" verify "<пакет>/manifest.json" --staged
```

Проверяется неизменность HEAD с момента снимка, совпадение индекса с кандидатом
и отсутствие staged изменений вне области ревью относительно HEAD, включая
обе стороны переименования. При чужих staged изменениях
не снимать их ради зелёной проверки: сохранить и изолировать работу по
фазе 3. Файлы процесса коммитятся отдельной проверенной операцией; не обходить
проверку добавлением чужих путей в scope задним числом. Между сверкой и commit
параллельных писателей нет. После commit сопоставить его diff с принятым пакетом.

Ограничения: помощник сохраняет обычные Git файлы и ссылки, не submodule,
FIFO или чужие репозитории. Содержательную полноту scope, достаточность тестов
и полномочия проверяет независимая роль — совпадение хешей их не доказывает.
Если Git-фильтр или нормализация строк меняет байты при добавлении в индекс,
строгая staged-проверка откажет. Это не разрешение пропустить её: согласовать
представление файлов и получить проверяемый кандидат в подходящей изоляции.
