# Переносимость методики между средами

Методика — это markdown-файлы, а не код. Она работает в любой среде, где есть
три вещи: **скилы** (папка с SKILL.md), **сабагенты** и **git**. Ниже — как
она ложится на конкретные среды и что придётся поменять.

## Матрица сред

| Что нужно методике | Claude Code | Codex CLI | Cursor / прочие |
|---|---|---|---|
| Папка скилов | `~/.claude/skills/` | `~/.codex/skills/`, в репо `.agents/skills/` | по документации среды |
| Правила проекта | `CLAUDE.md` | `AGENTS.md` | `AGENTS.md` (де-факто стандарт) |
| Сабагенты | штатно | `[features] multi_agent = true` в `~/.codex/config.toml` → `spawn_agent` / `wait_agent` / `close_agent` | зависит от среды; нет сабагентов → методика неприменима |
| Superpowers | плагин из superpowers-marketplace | `/plugins` или репозиторий obra/superpowers (в нём есть `references/codex-tools.md`) | по стандарту Agent Plugins 1.0 |
| MCP (context7) | `~/.claude.json`, JSON | `~/.codex/config.toml`, секция `[mcp_servers.*]`, TOML | по документации среды |
| Каталог компонентов и проверка живого интерфейса (по признаку) | MCP `shadcn` и `playwright` в `~/.claude.json` | те же серверы в `[mcp_servers.*]` `~/.codex/config.toml` | по документации среды; нет каталога — роль берёт эталоны вручную |
| Формат плагина | Claude-плагин или Agent Plugins 1.0 | Agent Plugins 1.0 | Agent Plugins 1.0 |

## Правила письма, сохраняющие переносимость

Соблюдать при каждой правке методики — иначе она незаметно прирастёт к среде.

1. **Никаких абсолютных путей к конфигам среды** в фазах и ролях. Писать
   «папка скилов», а не `~/.claude/skills/`. Конкретика — только в этом файле.
2. **Ссылки на скилы Superpowers — по имени** (`superpowers:brainstorming`),
   без указания, как они установлены.
3. **Специфика ОС и стека — только в приложениях** (конец файла, под явным
   заголовком «Приложение: пример для …») и в `reference/pitfalls.md`.
   Тело фазы обязано читаться стеко-независимо.
4. **Сабагент описывается ролью, а не механизмом запуска.** «Свежий
   исполнитель» — это роль; как именно среда его порождает, методику
   не касается.
5. **Ничего исполняемого.** Никаких скриптов и хуков внутри методики: они
   привязали бы её к формату конкретной среды.

## Установка в новой среде

1. Скопировать папку `autodev` в папку скилов этой среды.
2. Включить сабагентов (см. матрицу).
3. Поставить Superpowers.
4. Прописать context7 в формате конфига этой среды.
5. Прогнать фазу 0.A — она сама доложит, чего не хватает.

## Формат Agent Plugins 1.0

С августа 2026 действует вендор-нейтральный стандарт упаковки (OpenAI,
Microsoft, AWS, Anysphere, Vercel): папка с обязательным `plugin.json`,
необязательными `skills/` и `mcp.json`. Методика оформлена по нему —
файл `plugin.json` в корне. Это значит, что она ставится как плагин
в любой совместимой среде одной командой, без ручного копирования.

## Как методика развивается, оставаясь переносимой

Методика живёт в **своём git-репозитории**. Фаза 5 (ретро) каждого проекта
заканчивается коммитом сюда. Правило: коммит в методику обязан сопровождаться
строкой в CHANGELOG.md с номером версии, датой и проектом-источником урока —
иначе через пять проектов никто не вспомнит, откуда взялось правило и можно ли
его отменить.
