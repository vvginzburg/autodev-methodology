# Лимиты и конфигурация ролей в Codex

Качество принятого результата, время с переделками и внимание владельца —
основные показатели. Стоимость измеряется отдельно, не заменяет их.

По умолчанию роли наследуют модель текущей сессии. Отдельную модель задавать
только при согласованном распределении и поддержке инструментом. Не понижать
ревьюера относительно исполнителя ради экономии без проверенного основания.
В брифе указать наследование или запрошенную конфигурацию; в отчёте различать
её и фактически подтверждённую. Если среда последнюю не раскрывает, писать
«фактическая модель не подтверждена», не угадывать.

Доступные лимиты читать штатным инструментом; отсутствие данных не равно нулю.
Не обещать фиксированное пятичасовое окно для всех тарифов. Не покупать ресурсы
или погашать reset без явного поручения. При приближении лимита сохранить
проверенный результат и точку продолжения по фазе 3.

У исполнителя между изменениями — затронутые проверки; независимое ревью —
набор, достаточный для задачи и регрессий; финальная задача — все критерии.
Не повторять один и тот же зелёный прогон без изменения или нерешённой причины.
Числа Claude из reference/metrics.md — историческая база, не прогноз Codex.
