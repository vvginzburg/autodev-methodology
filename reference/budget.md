# Бюджет: токены, лимиты, модели

## Оценка проекта (базовая линия DocVault)
- Пара «исполнитель + ревьюер» на задачу средней сложности: ~100–170 тыс.
  токенов сабагентов (исполнитель 55–115, ревьюер 45–85).
- Оркестратор: ~10–20% сверху (брифы, вердикты, канцелярия).
- Проект на ~20 задач ≈ 2.5–4 млн токенов сабагентов → закладывать
  1–2 сессионных окна подписки и заметную долю недельного лимита топ-модели.

## Правила
1. Лимиты проверить и решение про Usage credits принять на фазе 2, не в момент
   остановки (остановка среди ночи теряет смену).
2. Сессионное окно ~5 часов: длинную фазу планировать так, чтобы обрыв
   по лимиту приходился на границу задач (коммит есть — потеря нулевая).
3. Экономия прогонов — самая большая статья: полный тест-набор на приёмке
   задачи; между red/green — только затронутые сьюты; полный прогон всех
   критериев — один раз в финальной задаче.
4. Модели по ролям: топовая — исполнитель сложных задач, ревьюеры,
   интеграционный, багфиксы; средняя — простые задачи, постановщик;
   дешёвая — канцелярия. Указывается параметром model при запуске агента.
5. Онбординг сабагента (чтение SPECIFICATION/DECISIONS/кода) ≈ 10–20% его расхода —
  это цена свежего контекста, она окупается качеством ревью; сокращать
  указателями на файлы, а не пересказом в брифе.

## Признаки перерасхода
- Сабагент > 150 тыс. токенов — задача слишком крупная, дели.
- Ревьюер дороже исполнителя — бриф ревью слишком широкий.
- Оркестратор > 25% проекта — активируй Постановщика/Канцелярию.
