# Фаза 1 — Проектирование

Цель: человек отвечает на ВСЕ вопросы один раз, здесь. После старта разработки
вопросов к нему нет. Время не жалеть: на DocVault ~3 часа проектирования
купили ~12 часов разработки без единого вопроса.

## Ход

1. **Брейншторм** (skill superpowers:brainstorming): сократический диалог,
   по одному вопросу за раз, для новичка — без жаргона, с примерами.
   Обязательно закрыть: модель данных глазами пользователя; эталон UX
   (например «как в Notes» — работает отлично); критерий качества с числом
   (не «маленький файл», а «≤700 КБ/страница»); объём v1 против v2 (YAGNI:
   каждое «нет» записать в RRR §решения, чтобы агент не переспрашивал);
   деньги и аккаунты (платные программы разработчика — активация занимает
   до 48 ч, оформлять на этой фазе!).
2. **Именованные риски реальных данных**: если продукт ест физический мир
   (камера/звук/сеть) — записать в RRR риск «синтетика ≠ реальность» с планом
   калибровки на приёмке (урок BF04).
3. **RRR.md** из шаблона. Самопроверка: заглушки, противоречия, двусмысленности.
4. **PLAN.md** из шаблона — здесь же, в сессии проектирования (у неё максимум
   контекста): задачи волнами, у каждой Files/Produces/Зависимости/Критерий.
   Правила декомпозиции: изоляция железа за протоколом — отдельная ранняя
   задача; «живой запуск каждой платформы» — в первой волне после появления UI,
   не в конце; ARCHITECTURE.md — предпоследняя задача; финальная — верификация
   всех критериев одним прогоном + REPORT.md.
5. **CLAUDE.md проекта** из шаблона: bootstrap, роли (ядро + активированные
   с полки), правила, факты окружения.
6. Ревью человеком RRR и PLAN. Только после его «ок» — фаза 2.

## Выход фазы
RRR.md, PLAN.md, CLAUDE.md в git-репозитории проекта (+ push в приватный GitHub).
