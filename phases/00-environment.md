# Фаза 0 — Проверка и подготовка окружения (первая на любом компе)

Цель: методика самодостаточна — на чистой машине сама проверяет зависимости
и подтягивает недостающее. Прогоняется в начале КАЖДОГО проекта (идемпотентна,
на настроенной машине занимает минуту).

## Чек-лист (AI выполняет сам, человека зовёт только где обязан)

### Универсальное
1. **git**: `git --version`. Нет (macOS предложит CLT) → человеку: «подтверди
   установку Command Line Tools в появившемся окне».
2. **Скилы Superpowers** — методика на них ссылается. Проверка: в списке
   доступных скилов есть superpowers:brainstorming, writing-plans,
   subagent-driven-development, test-driven-development,
   verification-before-completion. Нет → установить плагин Superpowers
   (`claude plugin install superpowers@superpowers-marketplace` или через
   /plugin в интерактивной сессии; после установки — перезапуск сессии) —
   если недоступно автоматически, дать человеку одну команду.
3. **gh (GitHub CLI) + авторизация**: `gh auth status`. Нет бинаря → поставить
   релиз в ~/.local/bin (без brew/sudo, если их нет — проверить!). Не
   авторизован → человеку: «выполни `gh auth login` в терминале» (интерактив).
4. **git identity**: `git config user.name/user.email` — пусто → спросить
   человека один раз, записать глобально.
5. **Особенности машины**: есть ли brew/sudo (на машине Вадима — НЕТ, тулчейн
   в ~/.local); зафиксировать факты в CLAUDE.md проекта.
6. **Сон**: способ держать машину бодрой (caffeinate на macOS) — просто
   проверить наличие.

### По типу проекта (пример: Apple-платформы)
7. **Xcode**: `xcodebuild -version`; симуляторы:
   `xcrun simctl list devices available | head`. Нет — человеку (App Store,
   долго).
8. **XcodeGen**: `xcodegen --version` или ~/.local/bin/xcodegen; нет →
   поставить релиз в ~/.local (+симлинк share — см. reference/pitfalls.md!).
9. **Аккаунт разработчика**: спросить человека, оформлен ли платный (если
   проекту нужны iCloud/устройства) — активация до 48 ч, запускать оформление
   немедленно, не блокируясь.

### Для других стеков
Добавлять секции по мере появления проектов (Node → ~/.local/node и т.д.) —
через ретро.

## Выход фазы
Таблица «зависимость → статус → что сделано» показана человеку; всё зелёное
или явно отложенное (напр., «Apple Developer активируется, не блокирует
фазы 1–3»). Красное и блокирующее → не идти дальше.
