# Фаза 2 — Проверка запуска Codex

Вход: ТЗ и план согласованы, есть поручение владельца на разработку, 0.B подтверждена. Согласование документов при поручении только проектировать не разрешает запуск. Согласие, уже имеющееся в
разговоре/DECISIONS, не запрашивать повторно. Записать основание в env-check.

1. Проверить полномочия: что делегировано системе, что оставлено владельцу,
   какие внешние операции разрешены, где остановиться. Разрешения инструментов
   проверить реальными необходимыми действиями; не выдавать себе права через
   файлы настроек. Устранимые без владельца препятствия устранить самостоятельно.
2. Проверить лимиты, если доступен инструмент их чтения. Не покупать ресурсы
   и не расходовать платный reset без поручения. План восстановления — шаблон
   AGENTS.md; длинный запуск не гарантирует переживания отключения машины.
3. Провести малый полный цикл по фазе 3: первая небольшая полезная задача
   согласованного плана → свежий исполнитель → реальный тест поведения →
   независимый свежий ревьюер → фиксация состояния → коммит. Её принять один
   раз, а не повторять затем как новую задачу. Можно использовать изолированный
   временный пример, если проект ещё не допускает малой задачи.
4. Во время цикла проверить: отчёты по контрактам, доступ ревьюера к файлам,
   запуск тестов им самим, записи STATUS при переходах, сохранение DECISIONS
   и PLAN. Проверить безопасный возврат при замечании, если он возник.
   Push проверять только при согласованном remote; локальный режим допустим.
5. Сохранить в env-check факты цикла (пути отчётов, команды, коммит, ограничения)
   и «фаза 2 завершена». Затем продолжать оставшийся план фазы 3 без нового
   запроса разрешения на уже согласованную разработку.

Независимое ревью недоступно или тест не проходит — цикл не принят. Устранить
причину, повторить затронутую проверку. Не заменять свидетельства обещанием
«инструменты настроены». Состояние ожидания и вопрос владельцу оформлять явно
только при реальной необходимости его действия.
