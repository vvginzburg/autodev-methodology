# CHANGELOG методики AutoDev

## v2.3 — 2026-08-30

Повод: подготовка к проекту в ещё не выбранном стеке; человек работает в роли
заказчика и идеолога, не разработчика. Источник — не ретро проекта, а разбор
методики перед стартом.

- **Роль «Исследователь стека и решений»** (roles/catalog.md): выбор стека по
  актуальным докам через context7, `reference/stack.md` проекта, точечные
  выжимки перед волнами с незнакомыми подсистемами.
- **Фаза 1 переработана**: явный раздел «роль человека — заказчик, не
  разработчик» с правилами разговора без жаргона; шаг 2 «Выбор стека»;
  шаг 5 «Аудит полноты ТЗ свежим агентом» с градацией дыр
  БЛОКИРУЮЩАЯ/ЗНАЧИМАЯ/ДЕЛЕГИРУЕМАЯ; названы три точки, где голос человека
  обязателен; послабление автономности для первой волны в незнакомом стеке.
- **Фаза 0 разделена на 0.A (до проектирования) и 0.B (после выбора стека)**;
  Apple-специфика вынесена в приложение; добавлены проверки сабагентов
  и context7; для 0.B задан обязательный минимум для любого стека.
- **reference/portability.md**: матрица сред (Claude Code / Codex CLI / прочие),
  пять правил письма, сохраняющих переносимость, порядок установки в новой среде.
- **plugin.json** по стандарту Agent Plugins 1.0 и **AGENTS.md** — методика
  ставится как плагин в любой совместимой среде.
- Принципы: добавлены №8 (стек — решение человека, работа про стек — AI),
  №9 (полнота ТЗ проверяется свежим агентом), №10 (методика не прирастает
  к среде). Прежний №8 «не изобретай — компонуй» стал №11.
- Первая задача плана в незнакомом стеке — «скелет + один зелёный тест».

## v2.0 — 2026-07-07 · источник: проект DocVault (~/DW/DocVault)

Первая версия в формате скила. Заменяет и поглощает
«~/Test claude/МЕТОДИКА-АВТОНОМНОЙ-РАЗРАБОТКИ.md» и «AUTODEV.md» (v1, 2026-07-06).

Что вошло из v1 без изменений (подтверждено проектом):

  долгоживущие.
